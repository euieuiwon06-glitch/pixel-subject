# Pixel Subject

웹캠 앞의 사람만 흑백 정사각형 픽셀로 옮겨 보여 주는 풀스크린 디지털 거울.
배경은 항상 완전한 검정(RGB 0,0,0)이고, 몸이 움직이면 픽셀이 관성으로 뒤처지고 흩어졌다가 다시 모인다.

## 실행

```bash
npm install
npm run dev        # http://localhost:8765 (run.bat 더블클릭으로도 실행)
npm run build      # dist/ 에 프로덕션 빌드
npm run preview    # 빌드 결과를 http://localhost:8765 에서 확인
```

- 카메라는 `localhost` 또는 HTTPS에서만 열린다.
- `npm run dev`/`build` 전에 `scripts/prepare-assets.mjs`가 MediaPipe wasm을 `public/mediapipe/wasm`으로 복사하고,
  인물 분할 모델(`selfie_segmenter.tflite`, 약 250KB)을 `public/models`에 한 번 내려받는다.
  그래서 실행 중에는 모든 리소스를 같은 서버에서 읽는다. 로컬 파일이 없을 때만 jsDelivr / Google Storage로 대체한다.
- 카메라 영상과 분석 데이터는 브라우저 밖으로 나가지 않는다. 저장도 하지 않는다.

## 디버그 패널

주소 뒤에 `?debug=1`을 붙이면 오른쪽 위에 조절 패널과 성능 수치가 나타난다. 없으면 아무 UI도 보이지 않는다.

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| pixel size | auto | 셀 크기(CSS px). auto는 화면 짧은 변 ÷ 58, 10–20px로 제한 |
| spring | 0.075 | 목표 위치로 당기는 힘. 낮을수록 늦게 따라온다 |
| friction | 0.8 | 속도 보존율. 높을수록 오래 미끄러진다 |
| scatter strength | 1 | 움직임에 따른 산란 세기 |
| trail lifetime | 600ms | 떨어져 나간 픽셀의 평균 수명. 개별 수명은 0.5–1.5배(300–900ms) |
| missing pixel ratio | 0.08 | 의도적으로 비우는 셀 비율(외곽은 최대 1.8배) |
| motion threshold | 520 | 이 속도(CSS px/s)에서 움직임 세기가 최대가 된다 |
| mask threshold | 0.5 | 인물로 판정하는 마스크 값(±히스테리시스) |
| grayscale contrast | 1.35 | 회색 대비 |
| tone levels | 4 | 회색 단계 수. 적을수록 픽셀 그래픽처럼 평평해진다 |
| dither | 0.85 | 4x4 Bayer 순서 디더링 세기. 0이면 단계만 끊는다 |

기본값은 `src/params.ts`의 `DEFAULTS`에서 바꾼다.

## 구조

```
src/
  main.ts        진입점, 페이지 이탈 시 정리
  app.ts         카메라·모델 로딩, 상태 문구, 렌더 루프, 적응형 성능
  camera.ts      getUserMedia(전면 우선) + 오류 분류
  segmenter.ts   MediaPipe Image Segmenter 래퍼 (GPU → CPU 대체)
  field.ts       셀 그리드, cover+좌우 반전 샘플링, 마스크 정리, 외곽·움직임 분석
  particles.ts   픽셀 파티클 풀: 목표 재배정, 스프링 물리, 산란, 잔상
  renderer.ts    WebGL2 인스턴싱 렌더러 (없으면 Canvas 2D)
  debug.ts       ?debug=1 패널
legacy/prototype.html   이전 단일 파일 프로토타입
```

## 동작 방식

1. **분석 (15–30fps)** — 영상을 셀 해상도에 맞춘 작은 오프스크린 캔버스(최대 512px 폭)에 그리고, 같은 캔버스를
   `selfie_segmenter`에 넣는다. 셀마다 마스크·휘도를 cover + 좌우 반전 좌표로 샘플링한다.
2. **마스크 정리** — 약한 시간 평활(65% 새 값) → 히스테리시스 이진화 → 가장 큰 덩어리의 3% 미만 조각 제거.
   셀 단위로 이진화하므로 가장자리는 부드러워지지 않고 계단형 실루엣이 유지된다.
3. **움직임** — 이전 틱과 현재 틱의 실루엣 깊이 지도(각 셀에서 배경까지의 거리)를 ±3셀 범위에서 맞춰 보고,
   차이가 가장 작은 정수 이동량을 몸 전체 이동으로 쓴다. 두꺼운 몸통이 결과를 좌우하므로 팔만 움직이면 이동량은 0이다.
   이동 없음보다 10% 이상 잘 맞을 때만 인정한다(데드존). 셀별 마스크 변화와 휘도 차이(데드존 0.07)는 국소 산란에 쓴다.
4. **목표 재배정** — 찾은 이동량만큼 모든 파티클의 목표 셀을 옮긴다. 파티클은 스프링으로 늦게 따라오므로 지연이 생긴다.
   마스크에서 사라진 셀의 파티클은 떠다니다 사라지고, 새로 생긴 셀은 근처에서 막 풀려난 파티클을 재사용하거나(팔 등 국소 움직임)
   불규칙한 위치에서 새로 태어나 모인다.
5. **산란** — `이동 반대 방향 × 외곽 강도 + (공간 노이즈 방향 + 몸 바깥 방향) × 외곽 강도`의 임펄스. 중심부는 약하게,
   외곽은 강하게. 움직일수록, 외곽일수록 스프링을 낮춘다. 외곽 픽셀 일부는 이동 반대편으로 잔상을 남긴다.
6. **렌더 (60fps 이상)** — 모든 파티클을 하나의 인스턴스 버퍼로 그린다. 위치·크기를 정수 픽셀에 맞춰 선명한 정사각형이 된다.

## 성능

- `devicePixelRatio`는 최대 1.5.
- 평균 45fps 미만이 2.5초 이어지면 픽셀 크기를 15%씩(최대 2.2배) 키워 파티클 수를 줄인다.
- 추론이 느리면 분할 주기를 30fps → 15fps까지 늦춘다. 물리는 60Hz 고정 스텝이고, 120/144Hz 화면에서는 스텝 사이 위치를 보간해 그린다.

## 접근성·예외

- `prefers-reduced-motion`: 산란 세기와 잔상 수명을 40%로 줄인다.
- 카메라 권한 거부 / 카메라 없음 / 다른 앱 사용 중 / 지원 안 되는 환경 / 모델 로딩 실패 — 작은 모노스페이스 문구와 다시 시도 버튼.
- 페이지를 떠나면 카메라 트랙, 애니메이션 프레임, 모델, WebGL 리소스를 정리한다.

## 제한 사항

- 한 명을 전제로 만들었다. 여러 명이 있으면 모두 픽셀이 되지만 이동량은 모든 실루엣을 한꺼번에 맞춰 하나만 계산된다.
- 몸 전체 이동은 틱당 최대 3셀까지 추적한다. 그보다 빠른 순간 이동은 새 픽셀이 생겨나 모이는 방식으로 표현된다.
- selfie_segmenter는 상반신/가까운 거리에 최적화돼 있어, 멀리 선 전신은 마스크가 거칠어질 수 있다.
